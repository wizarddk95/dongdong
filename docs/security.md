# 보안 모델

> English summary: [SECURITY.md](../SECURITY.md)

dongdong 은 **샌드박스 없이 사용자 OS 권한으로 도는 코딩 에이전트**다.
그게 이 도구의 설계이자 가장 큰 위험이다. 이 문서는 무엇을 막고, 무엇을 못 막고,
사용자가 무엇을 정해야 하는지 숨기지 않고 적는다.

한 줄로 줄이면: **에이전트가 할 수 있는 일 = 당신이 그 계정으로 할 수 있는 일.**

---

## 1. 신뢰 경계

```
    ┌─────────────────────────────────────────────────────────────┐
    │  당신의 OS 계정                                              │
    │                                                             │
    │   ┌───────────────┐   IPC    ┌───────────────────────────┐  │
    │   │  웹뷰 (React) │ ───────► │  Rust (Tauri)             │  │
    │   │  · 대화 렌더  │          │  · 셸 실행 (권한 그대로)  │  │
    │   │  · 도구 조립  │ ◄─────── │  · 파일 I/O (루트 제한)   │  │
    │   └───────┬───────┘          │  · SQLite · settings.json │  │
    │           │                  └─────────────┬─────────────┘  │
    │           │ (LLM 호출은 Rust reqwest 경유)  │                │
    └───────────┼────────────────────────────────┼────────────────┘
                ▼                                ▼
        LLM 공급자 API                   MCP 서버 (자식 프로세스)
        · 대화 원문이 나간다             · 당신 권한으로 돈다
```

신뢰하는 것: 당신의 OS 계정, 당신이 넣은 API 키, 당신이 등록한 MCP 서버.
신뢰하지 **않는** 것: LLM 이 만들어 낸 모든 문자열, 열어 본 프로젝트의 파일 내용,
MCP 서버가 돌려준 도구 결과, 웹에서 받아 온 무엇이든.

## 2. API 키는 어디에 있나

| | 위치 |
|---|---|
| 저장 | OS 앱 설정 디렉터리의 `settings.json` **한 곳** |
| Windows | `%APPDATA%\dev.dongdong.agent\settings.json` |
| macOS | `~/Library/Application Support/dev.dongdong.agent/settings.json` |
| Linux | `~/.config/dev.dongdong.agent/settings.json` |
| 형식 | **평문 JSON** |
| 권한 | unix 는 만들 때부터 `0600`. Windows 는 사용자 프로필 ACL |

프로젝트 DB(`.agent_workspace/local.db`)에는 **키를 넣지 않는다.** 프로젝트마다 다시
입력해야 하는 불편도 있지만, 진짜 이유는 실수로 커밋되는 걸 막기 위해서다.
(`.agent_workspace/` 는 만들어질 때 `*` 만 적힌 `.gitignore` 를 함께 만든다)

키가 나가는 곳은 하나뿐이다 — 해당 공급자의 API 엔드포인트. 텔레메트리도, 자동 업데이트도,
크래시 리포터도 없다.

### 키를 지켜 주는 것 세 겹

1. **네트워크 허용 목록 (Tauri capability).**
   웹뷰의 `fetch` 는 CORS 에 막히므로 LLM 호출이 Rust(reqwest)를 지나는데,
   그 통로가 `src-tauri/capabilities/default.json` 의 허용 목록으로 잠겨 있다:
   `api.anthropic.com` · `api.openai.com` · `generativelanguage.googleapis.com` ·
   `localhost` / `127.0.0.1`. **목록에 없는 주소로는 키가 나갈 수 없다.**
   (프록시를 쓰려고 사용자 지정 base URL 을 넣으면 여기서 막힌다. 정말 필요하면
   그 파일에 URL 을 추가하고 다시 빌드해야 한다 — 그 판단은 사용자 몫으로 남겨 뒀다)

2. **CSP.** `tauri.conf.json` 의 `app.security.csp` 가
   `default-src 'self'` · `script-src 'self'` · `connect-src 'self' ipc:` 로 잠겨 있다.
   혹시라도 웹뷰에서 스크립트 주입이 성립하더라도 바깥으로 신호를 보내지 못한다.
   원격 이미지도 로드하지 않는다(마크다운의 이미지는 링크로만 그린다).

3. **도구 출력 가리기 (`lib/ai/redact.ts`).**
   `cat ~/.config/.../settings.json` 한 줄이면 키가 도구 출력으로 되돌아오고,
   그건 DB 에 남아 **다음 턴에 공급자 서버로 나간다.** 그래서 도구 출력이 컨텍스트로
   들어가는 목(`clip()` — 내장 도구·MCP·스킬 본문이 전부 이 함수를 지난다)에서
   지금 설정에 든 키와 MCP 환경 변수 값을 문자열로 찾아 `[비밀값 가림]` 으로 바꾼다.
   공급자 오류 문구(`lib/ai/errors.ts`)도 같은 자를 지난다.

   **한계는 분명하다** — 모델이 키를 잘라 붙이거나(`echo ${KEY:0:20}`), base64 로
   바꾸거나, 파일로 복사해 두면 못 잡는다. 이건 방벽이 아니라 그물이다.
   진짜 방벽은 아래 4절이다.

## 3. 무엇을 막는가 (구현된 방어)

| 방어 | 어디 | 막는 것 |
|---|---|---|
| 경로 격리 | `src-tauri/src/paths.rs` `resolve_within()` | 파일 도구가 프로젝트 루트 밖으로 나가는 것. **심볼릭 링크/정션을 지나서도** 막는다 — 없는 경로는 존재하는 조상까지 먼저 풀고 나서 담장을 넘는지 본다 |
| 네트워크 허용 목록 | `src-tauri/capabilities/default.json` | 키가 임의의 주소로 나가는 것 |
| CSP | `src-tauri/tauri.conf.json` | 웹뷰 XSS 의 외부 통신·원격 리소스 |
| 비밀값 가리기 | `src/lib/ai/redact.ts` | 키가 대화 기록과 공급자 로그에 눌러 붙는 것 |
| 링크 스킴 검사 | `src/components/chat/Markdown.tsx` `safeHref()` | LLM 이 만든 `javascript:` 링크 |
| 원격 이미지 차단 | 같은 파일 | 마크다운 이미지로 만드는 추적·유출 픽셀 |
| 수식 렌더 격리 | KaTeX `trust: false` | `\href` 등 문서 밖으로 나가는 명령 |
| 훅 자리표 소독 | `src/lib/hooks.ts` `shellSafe()` | 훅 명령이 두 개로 갈리는 것. **공급자 에러 문자열은 아예 자리표로 주지 않는다** |
| 도구 출력 상한 | `clip()` 20,000자 | 검색·크롤 결과 하나가 컨텍스트를 통째로 먹는 것 |
| 설정 파일 권한 | `src-tauri/src/commands/settings.rs` | unix 에서 만드는 순간부터 `0600` (쓰고 나서 조이던 틈을 없앴다) |
| 프로세스 트리 정리 | `src-tauri/src/process.rs` `kill_tree()` | 중단·타임아웃 뒤에 손자 프로세스가 남는 것 |

## 4. 무엇을 못 막는가 (설계상 열려 있는 것)

여기가 중요하다. 아래는 버그가 아니라 **알고 연 문**이다.

### 4.1 프롬프트 주입 → 명령 실행

`execute_shell_command` 는 **승인 절차 없이** 곧바로 돈다. 그러므로 모델의 판단에
영향을 줄 수 있는 사람은 누구든 당신 계정으로 명령을 돌릴 수 있다. 경로는 여럿이다:

- 에이전트가 읽은 소스 파일의 주석
- `npm install` 로그, 테스트 출력, 웹에서 받아 온 문서
- MCP 서버가 돌려준 검색 결과
- 열어 본 프로젝트의 `AGENTS.md` (매 턴 시스템 프롬프트 **맨 앞**에 원문 그대로 실린다)
- 열어 본 프로젝트의 `.dongdong/skills/*/SKILL.md` (이름·설명이 매 턴 실리고, 본문은 `load_skill` 로)

**즉, 낯선 리포를 여는 것은 그 리포의 지시를 실행하는 것에 가깝다.**

줄이는 법:
- 신뢰하지 않는 리포는 **읽기 전용으로** 연다 — 설정 → 도구에서 `쉘 실행`·`파일 쓰기` 를 끈다.
- 설정 → 일반의 `AGENTS.md 자동 로딩` 을 끈다.
- 설정 → 스킬에서 프로젝트 스킬을 끈다.
- 정말 낯선 코드는 VM 이나 별도 사용자 계정에서 연다.

### 4.2 도구가 켜져 있으면 파일 격리는 안전장치가 아니다

`resolve_within()` 은 `read_file` / `write_file` 계열에만 걸린다.
셸이 켜져 있으면 `cd ..` 한 줄이면 그만이다. 경로 격리는 **실수로 인접 디렉터리를
건드리는 것**을 막는 장치지, 적대적 코드를 가두는 담장이 아니다.

### 4.3 MCP 서버는 당신 권한으로 도는 남의 코드

MCP 서버는 `settings.json` 에 적힌 명령을 자식 프로세스로 띄운다.
`npx some-mcp-server` 한 줄이 임의 패키지를 받아 당신 계정으로 실행한다는 뜻이다.
등록하기 전에 그 패키지를 확인하라. 서버에 넘긴 환경 변수 값은 가리기 목록에 함께 올라간다.

### 4.4 대화 원문은 공급자로 나간다

프로젝트 파일 내용, 셸 출력, 경로가 전부 프롬프트에 실린다. 사내 코드라면
공급자의 데이터 정책을 먼저 확인하라. 아무것도 내보내고 싶지 않다면
로컬 모델(`local:` 공급자)만 쓰면 된다 — [docs/local-llm.md](local-llm.md).

### 4.5 그 밖에

- **키 저장은 평문이다.** OS 키체인(Keychain / Credential Manager / libsecret)을 쓰지 않는다.
  디스크 암호화가 없는 기기에서는 파일을 읽을 수 있는 누구나 키를 가져간다.
- **`.agent_workspace/local.db` 는 암호화되지 않는다.** 대화 원문·파일 내용·셸 출력이
  평문으로 남는다. 리포를 공유할 때 이 폴더가 따라가지 않는지 확인하라(기본 `.gitignore` 가 막는다).
- **자동 업데이트가 없다.** 보안 수정이 나가도 사용자가 직접 받아야 한다.
- **코드 서명이 없다.** 배포본은 Windows SmartScreen / macOS Gatekeeper 경고를 낸다.

## 5. 안전하게 쓰는 기본값

1. **키는 최소 권한·최소 한도로.** 공급자 콘솔에서 이 앱 전용 키를 따로 만들고 지출 한도를 건다.
   한도는 유출의 마지막 방어선이다.
2. **낯선 코드에는 도구를 열지 않는다.** 처음 여는 리포는 읽기 전용으로 한 바퀴 돌아본다.
3. **인스펙터를 본다.** 무엇이 LLM 에 갔는지 노드마다 원문으로 열어 볼 수 있다.
   이게 이 도구의 존재 이유다 — 숨기지 않는 것.
4. **버전 관리 위에서 일한다.** 되돌릴 수 있으면 `write_file` 사고의 값이 싸진다.
5. **키를 잘못 흘렸다면 즉시 폐기(revoke)한다.** 가리기는 그물일 뿐이다.
